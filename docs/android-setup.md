# 安卓方案搭建

安卓上这件事比 iOS 简单得多：系统直接提供了读通知和往通知里回复的
官方 API，不需要 root，也不需要碰微信本身。

**引擎跑在 App 里**，不需要服务器、不需要电脑、不需要局域网——
装完 APK 打开开关就能用。这一点是刻意的：让一个不写代码的人去装
Termux 敲命令是不现实的。

> 给完全不懂技术的人看的版本：[../新手指南.md](../新手指南.md)。
> 这份文档是给要改代码的人看的。

## 两种实现，主次分明

| | 主力：通知直接回复 | 兜底：无障碍操作界面 |
|---|---|---|
| 文件 | `WeChatNotificationService.kt` | `WeChatAccessibilityService.kt` |
| 原理 | 微信通知自带「回复」按钮（RemoteInput），往里灌文字并触发 | 读屏幕控件树，找输入框打字点发送 |
| 需要权限 | 通知使用权 | 无障碍权限（**权限很大**） |
| 微信要在前台吗 | ❌ 不需要 | ✅ 需要停在聊天页 |
| 消息完整度 | 通知可能截断长消息 | 完整 |
| 免打扰会话 | ❌ 收不到 | ✅ 能处理 |

**默认只开主力方案就够了。** 只有当你遇到「通知没有回复按钮」或
「会话开了免打扰」时，才需要额外打开无障碍。

## 两种回复方式

设置页上的「怎么回」决定走哪条路，对应 `ReplyMode`：

### KEYWORD —— 本机关键词匹配（默认）

`ReplyEngine.kt` 是 `core/engine.py` 的 Kotlin 移植，行为必须保持一致，
尤其是判断顺序。全程不联网，一个字节都不往外发。

局限很清楚：只能回你事先想到的那几句。这跟当年 QQ 的自动回复是同一个东西。

### AI —— 交给模型按人设生成

`AiWriter.kt` 里两个实现，用户二选一（`AiSource`）：

| | `OWN_KEY` → `OpenAiCompatibleWriter` | `RELAY` → `RelayWriter` |
|---|---|---|
| 打给谁 | 用户自己注册的接口 | 本仓库的 `server/app.py` |
| 用户要填 | 接口地址 + API Key + 模型名 | 地址 + 口令 |
| 人设存在哪 | 手机本地 | 对方服务器的 `config.yaml` |
| 依赖别人吗 | ❌ 不依赖 | ✅ 对方关机就不回了 |
| 消息经过谁 | 用户选的那家接口 | 对方的服务器 + 那家接口 |

`OpenAiCompatibleWriter.PRESETS` 里预置了豆包 / DeepSeek / 通义千问 /
智谱 GLM / Moonshot 的地址和模型名，都是 OpenAI 兼容格式，国内直连。
设置页把它们做成了按钮——「接口地址填什么」是非技术用户最容易卡住的地方。

**豆包放第一个**：这套东西要的是「聊天像真人」而不是解数学题，
它的中文口语是这几家里最自然的。Python 端有同一张表
（`core/providers.py`），两边保持一致。

火山方舟的 `model` 字段比较特殊：模型 ID（`doubao-seed-1-6-251015`）
和推理接入点（`ep-` 开头）都接受，而模型 ID 带日期后缀会随版本变。
所以 `Preset` 带一个 `note` 字段，选中时显示在设置页上——
不说清楚的话，用户只会看到「不回复」而不知道为什么。

要加一家，往 `PRESETS` 里加一行就行，只要对方支持
`POST {baseUrl}/chat/completions`。记得 `core/providers.py` 也加一条。

### 失败要能照着修

非技术用户不会看 logcat，所以 `AiWriterException` 把 HTTP 状态码
翻译成能直接照着做的话（401→key 不对、404→模型名不对去控制台复制、
402→余额不足），经由引擎的 `Decision.reason` 显示在「试一试」里。

引擎照样捕获它并退化成「不回复」，线上行为没有变化——变的只是
用户能不能自己查出问题。

## 开场问答

`engine/SetupWizard.kt` + `SetupWizardActivity.kt`，装完第一次打开自动进。
对应 Python 版的 `core/wizard.py`（`python3 -m core.wizard`）。

十道题，八道单选，选完直接跳下一题。答案按**确定的规则**拼装成人设、
关键词规则和兜底话术——不是拿去喂模型润色的。理由有三个：

- 人设本身就是提示词，不该是概率性的，否则每次生成的都不一样
- 拼装是纯函数，可以单测；「让模型写提示词」测不了
- 没有 key 也能用：关键词模式的人同样需要一套像样的文案

地基是 `VOICE / APPOINTMENT / PROGRESS / STRANGER` 四张表，
四种说话方式 × 四类常见情况共十六句话。加新情况就加一张表 +
一道题，两端各加一次。

**两端的问题 id 和顺序必须一致**，`SetupWizardTest.bothImplementationsAskTheSameQuestions`
和 `test_both_implementations_ask_the_same_questions` 分别钉住了这一点。
不一致的话，同一个人在电脑和手机上生成的人设不一样，语气就对不上了。

`SetupWizard.applyTo` 只覆盖 persona / rules / fallbackText，
开关、限流、黑名单、AI 设置一概不动——重答一遍不该冲掉用户其他设置。

## 判断顺序（这一段别改）

```
总开关 → 空消息 → 硬性敏感词 → 黑名单 → 屏蔽词 → 白名单
→ 会话类型 → 时段 → 频率限制 → [AI 生成 | 关键词规则] → 兜底
```

AI 分支在**所有安全判断之后**。模型只决定「说什么」，不决定
「该不该说」——后者不能交给一个概率性的东西。

具体后果：

- 含转账/红包/验证码/借钱等字样的消息**压根不会离开手机**
- 黑名单里的人、按策略不回的群消息，同样不会发给模型
- 冷却期内的消息不会调接口（每次调用都是钱）
- 接口失败时直接跳过，**不记进配额**、不重试、**不退回关键词文案**
  （用户选了 AI 就说明他不想发罐头话，冒出一句风格完全不同的句子更糟）

`AiReplyTest.kt` 把这几条都钉住了。改引擎之前先看那个文件。

## 对话记忆

`ConversationMemory.kt`：每个会话留最近 8 轮、1 小时过期，只在内存里，
不落盘。

没有上下文是「像机器人」的主要来源：对方说「那明天呢」，模型看不到
前一句就只能瞎猜。反过来，太老的上下文也会误导，所以窗口刻意开得很小。

记忆挂在 `AiWriter` 实例上，所以 `EngineHolder` 只在 AI 设置真的变了
（`Storage.aiWriterKey` 变了）才重建生成器——每条消息重建就等于每条消息失忆。

## 编译

不用本地装 Android SDK，GitHub Actions 会编：
`.github/workflows/build-apk.yml`，产物在 Actions 页面的 Artifacts 里。
CI 会先跑单测再编 APK，测试挂了就不出包。

本地编（需要 SDK）：

```bash
cd android
./gradlew testDebugUnitTest   # 引擎单测，纯 JVM，不需要设备
./gradlew assembleDebug
adb install app/build/outputs/apk/debug/app-debug.apk
```

## 配置和授权

打开「微信自动回复」App：

1. 点「授予通知使用权（必须）」→ 在系统页面里找到本应用并打开
2. 选「怎么回」；选了 AI 就再选「AI 从哪儿来」并填对应的字段
3. 在「试一试」里输几句，确认语气和拦截行为都对
4. 点「保存设置」
5. 把最上面的大开关拨到开

配置每条消息都重新读，改完立刻生效，不需要重启服务。

（可选）无障碍：系统设置 → 无障碍 → 已下载的服务 → 微信自动回复。

## 常见问题

**日志里什么都没有**
通知使用权没给，或者给了之后没重启服务。到系统设置里关掉再打开一次。

**「通知没有回复入口，跳过」**
ROM 剥掉了 RemoteInput（小米、部分定制系统上出现过）。
开无障碍方案兜底，或者去微信通知设置里确认「显示消息详情」是打开的。

**回复发出去了但对方没收到**
检查微信是不是被系统「电池优化」杀了后台。把微信和本 App 都加进
省电白名单。

**AI 模式一直不回**
看 `OpenAiWriter` 的日志。常见是 key 填错（401）、余额用完（402/429）、
地址没填（点一下厂商按钮）。设置页的「试一试」会真的调一次接口，
用它排查最快。

**回出来像客服**
人设是空的或者太笼统。`identity` / `playbook` 写具体，`examples` 一定要
用自己真的会说的话——那几条例子比任何形容词都管用。

## 安全提醒

这个 App 拿到通知使用权后，**能读到你手机上所有 App 的通知**。
代码里只处理 `com.tencent.mm` 一个包，消息内容不落盘，但这是靠代码自觉，
不是靠系统限制。

AI 模式下消息会发给用户自己选的接口——这是这个模式的前提，
设置页和新手指南里都写明了。介意的就用关键词模式。

所以：**只装你自己编译的版本，或者从本仓库 Actions 里下的版本。**
