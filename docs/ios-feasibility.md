# iOS 到底能不能做？—— 逐条讲清楚

先给结论，再给依据。

## 一句话结论

**未越狱的 iPhone 上，「装个 App 就能自动回微信」这件事不存在。**
不是难，是被 iOS 沙盒从根上堵死了。但 iOS **有** 三条能真正跑起来的路，
本仓库实现了其中两条。

---

## 为什么「纯 App 插件」在 iOS 上不可能

微信自动回复需要两个能力：**读到别人发来的消息**、**代替你发出消息**。
iOS 对这两件事的限制是：

| 你可能想到的办法 | 在 iOS 上的真实情况 |
|---|---|
| 写个 App 读微信通知 | ❌ iOS 没有安卓 `NotificationListenerService` 的对应物。第三方 App 拿不到别的 App 的通知内容。 |
| 用「通知服务扩展」拦截 | ❌ `UNNotificationServiceExtension` 只能改**你自己 App** 的通知，碰不到微信的。 |
| 快捷指令（Shortcuts）自动化 | ❌ 「收到消息时」这个触发器只对系统「信息」App 生效，微信没有暴露任何可触发的意图。只能做到「打开微信」这种程度。 |
| 读微信的数据库 | ❌ 沙盒隔离，别的 App 的 Documents 目录你根本看不见。 |
| Siri / 快捷回复 | ❌ 微信在锁屏通知上确实支持快捷回复，但那是用户手点的，没有编程接口。 |
| 无障碍（辅助功能） | ❌ iOS 的 VoiceOver 等辅助功能不像安卓那样开放给第三方 App 做 UI 自动化。 |

这一列全是 ❌，是 iOS 的设计选择，不会因为换个写法就绕过去。
任何声称「iOS 免越狱后台自动回微信」的方案，要么是在用下面的路线 A，
要么是在骗你。

---

## 三条真正可行的路

### 路线 A：UI 自动化（Appium + WebDriverAgent）— 免越狱 ✅ 已实现

**原理**：不去读微信的数据，而是像一只机械手一样操作屏幕——扫会话列表、
点开有红点的会话、用 OCR 之外的辅助功能树读文字、敲键盘、点发送。

**实现**：[`ios/appium/wechat_ios_bot.py`](../ios/appium/wechat_ios_bot.py)

| 维度 | 情况 |
|---|---|
| 需要越狱 | 否 |
| 需要什么 | 一台 Mac + Xcode、真机 iPhone、Apple 开发者账号（免费账号也行，但证书 7 天过期） |
| 手机能否正常用 | 运行期间微信必须在前台，手机基本被占用 |
| 后台运行 | ❌ 做不到。锁屏或切走 App 就停 |
| 消息类型 | 只能处理文本；图片、语音读不出内容 |
| 稳定性 | 中等。微信改版会导致控件定位失效，需要调 `SELECTORS` |

**适合谁**：能把一台备用 iPhone 插在 Mac 上当「值班机」的人。
不适合当日常主力机用。

详细搭建步骤见 [`ios/appium/README.md`](../ios/appium/README.md)。

---

### 路线 B：注入式插件（Theos tweak / dylib 注入）— 需越狱或重签名 ✅ 已实现

**原理**：把一个动态库注入微信进程，直接 hook 它的 Objective-C 方法。
`CMessageMgr` 收到消息时我们插一脚，判断要不要回，然后调它自己的
`SendTextMessage:` 发出去。这才是字面意义上的「微信插件」。

**实现**：[`ios/tweak/Tweak.x`](../ios/tweak/Tweak.x)

| 维度 | 情况 |
|---|---|
| 需要越狱 | 越狱机直接装；未越狱可以走「重签名 IPA + 注入 dylib」（Sideloadly / TrollStore） |
| 手机能否正常用 | 能，插件在后台跑，微信不用保持前台 |
| 后台运行 | ✅ 微信活着它就活着 |
| 消息类型 | 文本完整拿到，且能拿到 wxid、群 id 这些 UI 层拿不到的信息 |
| 稳定性 | 高（只要方法签名没变） |
| 风险 | 最高。见下面「风险」一节 |

**关键坑**：`Tweak.x` 里的类名和方法签名（`AsyncOnAddMsg:MsgWrap:`、
`SendTextMessage:toUsr:msgText:`）来自微信 iOS 8.0.x。微信每次大版本
更新都可能改。**签名对不上时 hook 会静默失效**——不崩溃，就是什么都不发生。
适配方法见 [`ios/tweak/README.md`](../ios/tweak/README.md)。


---

### 路线 D：侧载改包微信（不越狱）— 技术上可行，但不建议 ⚠️

**原理**：和路线 B 一样是注入 dylib，区别在于不越狱，而是把 dylib 打进
微信 IPA 后重签名侧载。

**这条能满足「不越狱 + 手机上直接跑 + 后台常驻」**，所以值得认真评估一次。
结论是：技术上通，但代价超过收益。

#### 签名怎么解决

| 工具 | 有效期 | 要不要电脑 |
|---|---|---|
| **TrollStore** | 永久 | 否 |
| **SideStore** | 7 天，设备上自动续 | 仅首次配对 |
| **Sideloadly / AltStore** | 7 天（免费 ID）/ 1 年（付费账号） | 每次续签都要 |

- **TrollStore 已经不可用**。它靠的 CoreTrust 漏洞在 iOS 17.0.1 被修复，
  iOS 18 / 26 / 27 均不支持，官方明确表示除非出现新漏洞否则永不支持。
- **SideStore 是目前唯一能「不靠电脑续签」的**：Mac 上一次性生成配对文件，
  之后靠设备上的 VPN 助手自己刷新证书。免费 Apple ID 限 3 个 App。

#### 真正的坑不在签名，在安装包

**要注入 dylib，先得有一个解密过的微信 IPA。** App Store 下载的是
FairPlay 加密的，直接注入无效。拿到解密版只有两条路：

1. **用越狱设备脱壳** —— 那就绕回越狱了，没有意义
2. **从第三方网站下别人脱好的** —— 等于把微信账号交给一个陌生人编译的
   客户端。这个二进制里有什么，你无从验证

第 2 条的风险**高于越狱你自己的手机**：越狱至少东西还在你自己设备上、
插件是你自己编译的；下载来路不明的微信客户端则是把登录态直接交出去。

#### 其他成本

- 续签链路脆：配对文件会失效、VPN 助手 App 会被下架、iOS 更新会打断
- 改包微信的封号风险高于桌面端方案
- 侧载版会替换 App Store 版，需要重新登录

#### 什么时候才值得考虑

只有当**「Mac 必须能关机」是硬需求**，并且你有能力自己脱壳（有一台可越狱
的旧设备专门用来 dump IPA）时。否则路线 C（Mac 常开）在各个维度都更划算。

---

### 路线 C：macOS 微信代打 — 最省事 ✅ 已实现

**原理**：微信支持手机和 Mac 同时在线，收到的是同一份消息。
在 Mac 上自动回复，对方看到的效果和你用手机回一模一样。

**实现**：[`macos/wechat_mac_bot.py`](../macos/wechat_mac_bot.py)

| 维度 | 情况 |
|---|---|
| 需要越狱 | 否 |
| 需要什么 | 一台开着的 Mac，授予辅助功能权限 |
| iPhone 是否被占用 | ❌ 完全不占用，手机正常使用 |
| 后台运行 | ✅ Mac 开着就行 |
| 稳定性 | 中等，微信 Mac 版改版会影响控件定位 |

**如果你的目标是「我的微信能自动回消息」而不是「必须在 iPhone 上跑代码」，
这条是性价比最高的。**

---

## 怎么选

```
你有一台能常开的 Mac 吗？
├─ 有 → 路线 C（macOS 代打）。最省事，iPhone 完全不用动。
│        一条命令搞定：bash scripts/macos-setup.sh
└─ 没有
    ├─ 手机已越狱 → 路线 B（注入插件）。功能最完整。
    ├─ 不想越狱，但「Mac 必须能关机」是硬需求
    │   → 路线 D（侧载改包微信）。但先看清楚它的代价：
    │     你得从第三方拿解密版微信 IPA，风险比越狱自己的手机更大。
    ├─ 有 Mac、能牺牲一台备用 iPhone → 路线 A（Appium）
    └─ 都不行 → 用安卓。安卓上服务能直接跑在手机里：
                 bash scripts/termux-setup.sh
```

**大多数人的答案是路线 C。** 「iPhone 上直接跑」听起来更优雅，但在
不越狱的前提下，它要求你信任一个来路不明的微信二进制——为了省下
「Mac 保持开机」这一件事，这个交换不划算。

## 风险，说在前面

这几条路都在做微信官方没有开放的事情，客观上存在以下风险，你需要自己
判断是否接受：

1. **账号风控**。自动化行为（尤其是秒回、高频回复、多设备异常登录）
   可能触发微信的风控，轻则功能受限，重则封号。本仓库的引擎默认带了
   随机延迟、单会话冷却、每日上限、全局限流，就是为了把行为拉回到
   「像人」的范围，但**不能保证不被判定**。
2. **越狱 / 重签名（路线 B）本身会降低设备安全性**，且违反微信的用户协议。
3. **误回的代价**。引擎内置了一组硬性敏感词（转账、红包、验证码、借钱……），
   命中就绝不自动回复，且这个判断排在所有频率逻辑之前。请不要删掉它们。
4. **别人不知道在跟机器人说话**。默认配置会在回复末尾加「（自动回复）」，
   建议保留。

建议的使用方式：**只对确定的人、确定的场景开自动回复**（用 `allow_contacts`
白名单），而不是对所有人全天开启。
