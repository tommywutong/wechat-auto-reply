# 模块记忆与文档架构设计

## 目标

把当前集中在根目录 `MEMORY.md` 的项目知识拆到八个一级模块，使 agent 先读全局规则，随后只读取任务涉及的模块记忆；同时为开发者提供与源码就近的模块说明。

## 采用的结构

每个模块包含一对文件：

- `MEMORY.md`：面向 agent，记录入口、稳定约束、影响面、验证方式和继续下钻的路径。
- `README.md`：面向开发者，解释模块目的、架构、主要文件、使用方式与限制。

模块列表：

1. `core/`
2. `server/`
3. `macos/`
4. `macos/TraceMemoAutoReplyApp/`
5. `android/`
6. `ios/`
7. `scripts/`
8. `docs/`

根目录 `AGENTS.md` 保存所有任务都必须遵守的安全和工作规则。根目录 `MEMORY.md` 缩减为模块索引、跨模块数据流和选择指南，不再重复各模块的实现百科。

## 渐进式披露流程

```text
根 AGENTS.md
  -> 根 MEMORY.md
  -> 当前模块 MEMORY.md
  -> 当前模块 README.md（需要背景时）
  -> MEMORY.md 指定的源码、测试或专项文档
```

默认只打开一个模块记忆。跨端决策语义、配置契约、HTTP schema、服务控制或隐私边界发生变化时，再读取受影响的其他模块。

## 内容边界

- 模块记忆只保留能指导修改和验证的稳定知识，不记录测试数量等易漂移快照。
- 模块 README 不复制已有长篇专项文档，而是给出本模块地图并链接权威说明。
- 源码和测试始终高于记忆与说明文档。
- 不把真实配置、Token、联系人、聊天正文、日志或截图写入任何文档。

## 验证

- 检查 16 个模块文件均存在且非空。
- 检查根索引能到达所有模块记忆和 README。
- 检查模块内引用的源码、测试和专项文档存在。
- 检查没有尾随空白、失效 Markdown 链接或秘密样例。
- 本次不改业务代码，因此不以代码测试替代文档结构验证。
